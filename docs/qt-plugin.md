# The Qt image plugin

`qt/` holds a small C++ plugin for Qt 6 that lets Qt programs that read pictures through Qt's image plugins, such as Gwenview and Dolphin's Information panel, open Slerp's files.  Building and installing it is described in the [README](../README.md#the-qt-image-plugin); this page says how it behaves.  The timings below were measured on one Linux laptop with an RTX 5070 Ti.

- Textures and pictures no other Qt plugin reads (KTX2, KTX, ASTC, PVR, PKM, BLP, XNB, Quake sprites, Aseprite, Tiled and LDtk maps, FITS, XISF, DPX, Cineon, PAM, farbfeld and the retro computer formats) read as ordinary pictures at their own size (or the size the program asks for), with alpha.  Cubemaps read as a cross.  DDS, Radiance HDR, EXR, TGA, PSD and PNG stay with the plugins that already read them.
- Heightmap-named PNGs have their own MIME type (`image/x-heightmap`, so Dolphin sends them to Slerp's thumbnailer), which Gwenview refuses unless some image plugin claims it.  The plugin claims it, and Gwenview then reads them with Qt's own PNG reader, as a plain PNG.
- Models, point clouds, levels, scenes (Godot, Unity, Blender) and materials read as 36-frame animations of one turn, 512 pixels square unless the program asks for another size.  Each frame is the thumbnail of the model turned by that much: same lighting, same framing.  Materials turn on a ball, even when they ship a preview picture.
- Qt asks every image plugin about every picture it opens, so the plugin's checks are a comparison of the file's extension with its own and, only when nothing else recognised a file, a look at its first bytes for strong signatures.  Reading 1000 small PNGs and JPEGs takes the same time with and without it (about 0.73 s); opening each costs about 1.5 microseconds more.
- A model's first read is one picture: its thumbnail from the freedesktop thumbnail cache, or the first frame alone from the helper (20-140 ms).  Programs that want one picture, such as thumbnail generators, stop there.  The turntable (80-340 ms in all) is fetched only when a second frame is read, on a thread of its own, and a GUI thread is handed the first picture again until it arrives, so Dolphin's Information panel shows the thumbnail and then the model starts turning, without Dolphin ever waiting.  Other threads wait for the real frames.
- Anything that goes wrong (no helper, a broken file, the helper killed) is meant to give no picture or an animation that stops, within 2.5 s at worst, rather than a crash or a hang.  The helper is started through `posix_spawn` and a shell, so nothing forks inside the program that loaded the plugin.
- `qt/tests/check.cpp` builds `slerp-qt-check`, which tests the plugin from outside: `selftest` (format table, content checks, the protocol client against a misbehaving fake helper), `read` and `movie` (as Gwenview and Dolphin read files), and `bench` (ordinary images with and without the plugin).  `QT_PLUGIN_PATH=local/target-qt/plugins` loads the plugin from the build tree, and `QT_LOGGING_RULES=slerp.qimage.debug=true` says why a read failed.
