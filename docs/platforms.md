# Windows and macOS

Linux is Slerp's main platform; Windows 11 (x86_64) and macOS (Apple Silicon) run the command line and the viewer, and get thumbnails in Explorer and Finder.  This page describes how those builds are made and how they fit into each system.  Installing them is described in the [README](../README.md#windows).

- **Windows** (x86_64), cross-compiled on Linux: `tools/build-windows.sh` builds `slerp.exe`, Explorer's thumbnail handler `slerp_shell.dll` and the viewer launcher `slerpw.exe`, all with the MinGW runtime linked in, so they need no other DLLs, each with Slerp's icon and version information (`data/windows/slerp.rc`), and packs them with a short `README.txt` (`data/windows/`) as `local/dist/Slerp-windows-x64.zip`.  It needs rustup's toolchain with the `x86_64-pc-windows-gnu` target, the mingw-w64 posix-threads compilers and binutils, and libclang.  `tools/build-windows.sh cargo check` runs any cargo command for Windows.
- **The Windows installer** is made from the zip's files on Windows with Inno Setup (`packaging/windows/slerp.iss`; the release workflow does it on GitHub's Windows machines).  It installs for the current user without administrator rights into `%LOCALAPPDATA%\Programs\Slerp`, runs `slerp register` after copying and `slerp unregister` before uninstalling, and adds `slerpw.exe` to the Start menu.  Explorer, the thumbnail helper and the viewer keep files of the old version open, and Windows can rename such a file but not replace or delete it, while a per-user installer can't have it replaced at the next restart.  So an upgrade renames the programs in use to `<name>.<n>.old` beside the new ones (deleted at a later install once nothing holds them), and uninstalling moves them into `%TEMP%`, so the folder goes away without Explorer being restarted.  Explorer goes on using the old thumbnail handler until it lets go of it or the user signs out.  `tools/test-windows-installer.ps1` installs and uninstalls silently and checks the files, registry entries and Start menu entry each leaves.
- **Explorer** gets thumbnails from `slerp_shell.dll`, an `IThumbnailProvider` COM server, for the formats Slerp makes thumbnails of; `.png` only for 16-bit greyscale heightmaps, since other PNGs go on to Windows' own thumbnailer.  `slerp register` registers it for the current user without administrator rights, with an "Open with" entry that runs the viewer through `slerpw.exe`, a Windows-subsystem launcher, so no console window flashes up; `slerp unregister` (or `regsvr32 /u`) removes both.  Explorer hands the real path only to handlers it loads into its own process, and formats with neighbouring files need it (glTF's `.bin` and textures, MaterialX textures, a BSP's `.lit`, an MD2's skin), so the handler runs inside Explorer but draws nothing there: it sends the path over a per-user named pipe to `slerp helper`, which it starts on demand and which keeps the GPU loaded for every Explorer window and file dialog until two idle minutes have passed.  On Direct3D's WARP software renderer, in a Windows 11 virtual machine, the first 3D thumbnail took about 1.5 s, including starting the helper, and later ones 30-600 ms.  The preview pane (Alt+P) shows the same picture at its own size.  Explorer keeps the DLL loaded, so replacing it by hand needs Explorer restarted (Task Manager, Windows Explorer, Restart) or a sign-out; the installer works around it.  With UAC switched off, Explorer runs elevated and ignores per-user shell extensions; Windows' default, UAC on, works.
- **macOS** (Apple Silicon), built on a Mac over SSH from Linux: the Mac must see the source folder at the same path (shared with Syncthing, for example), and `SLERP_MAC=user@host tools/build-macos.sh` waits until the Mac's copy matches, then runs `tools/macos-app.sh` there, which makes `Slerp.app` (the viewer, with a Quick Look thumbnail extension inside, ad-hoc signed, with the icon from `packaging/macos/icon-1024.png`), packed as `local/dist/Slerp-macos-arm64.zip` and as a disk image, `Slerp-macos-arm64.dmg`, with a link to Applications.  `tools/build-macos.sh install` also installs the app in the Mac user's `~/Applications` and registers its file types and extension; `tools/build-macos.sh uninstall` removes it again.  It logs in with SSH keys, or with a password from `SSHPASS`, and settings for one machine can go in `local/build-macos.env`; `tools/build-macos.sh cargo test -p slerp-helper` runs any cargo command there.  On a Mac itself, run `tools/macos-app.sh [install | uninstall]`, which needs Rust and Apple's Command Line Tools (`xcode-select --install`), not Xcode.
- **Finder** gets thumbnails from the Quick Look extension for every format macOS doesn't know itself (FBX, VRM, MagicaVoxel, Quake and Doom files, KTX2, materials, point clouds and splats, palettes, retro art, science and CAD formats; the type declarations are generated from the format table).  Quick Look keeps the formats macOS declares itself (glTF and GLB, OBJ, STL, PLY, COLLADA, USD, KTX, ASTC, DDS, Radiance HDR, PNG) for Apple's own thumbnailers, whatever an app asks, so those show what macOS draws: nothing at all for GLB.  The extension is sandboxed with access to the one file, so formats that read neighbouring files (a material's textures, an MD2's skin) show what the file alone holds.  It can be switched off in System Settings (General, Login Items & Extensions, Quick Look) or with `pluginkit -e ignore -i com.slerp3d.Slerp.Thumbnails`.
- Slerp appears in Finder's Open With menu for all of these formats.  It is the default viewer for the formats macOS doesn't know, and also for OBJ, STL, PLY, COLLADA and USDA, which Preview and TextEdit claim only as 3D content or text in general; GLB, USDZ, KTX, DDS, HDR and PNG stay with Preview.  Get Info's "Open with" changes that per type.  A file opened while the viewer runs replaces the one it shows.
- Uninstalling leaves the settings in `~/Library/Application Support/Slerp` and the extension's sandbox folder `~/Library/Containers/com.slerp3d.Slerp.Thumbnails`; delete them by hand if wanted.  Gatekeeper blocks a copy of the ad-hoc-signed app downloaded with a browser, until it is allowed in System Settings, Privacy & Security, "Open Anyway", or its quarantine is cleared with `xattr -dr com.apple.quarantine /Applications/Slerp.app`; a copy downloaded with curl carries no quarantine.
- The thumbnail helper runs on macOS (its socket is in `$TMPDIR/slerp/`), for `slerp thumbnail` on the command line; the Quick Look extension doesn't need it, since Quick Look keeps the extension's process, and with it the GPU, loaded between thumbnails.  On Windows `slerp thumbnail` renders in its own process, and `slerp helper` is Explorer's helper instead.
