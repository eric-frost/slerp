Slerp

Thumbnails for the files your file manager doesn't preview.

Thumbnails and a viewer for about 200 formats: 3D models, GPU textures, HDR skies, game levels, Gaussian splats, voxels, retro art, CAD drawings and scans. For Linux, Windows and macOS. Open source, and not released yet.

File managers

Thumbnails in the file manager

Most file managers show a generic icon for a .glb, a .ktx2 or a .bsp. With Slerp installed they show the model, the texture or the level. Slerp uses the thumbnail system each desktop already has.

Linux

Dolphin, GNOME Files, Nemo, Caja, Thunar and PCManFM-Qt, through the freedesktop thumbnailer standard. An optional Qt plugin lets Gwenview open textures and turns models slowly in Dolphin's Information panel.

Windows 11

Explorer, through a thumbnail handler registered for your account only. No administrator rights, and slerp unregister puts back whatever was there before.

macOS

Finder, through a Quick Look extension that covers the formats macOS doesn't know itself.

The GPU stays loaded

Starting a GPU takes 100 to 800 ms, so the first thumbnail starts a helper process that keeps the GPU loaded. On a laptop with an RTX 5070 Ti, each thumbnail after that took a few milliseconds. The helper quits after two idle minutes.

You choose the file types

Thumbnails are on for formats your desktop can't preview, and off for ordinary pictures it already draws. Switch any of them under Settings, File Types, or with slerp associate. slerp associate --reset puts back exactly what was there.

The viewer

The viewer

Double-click one of those files and Slerp picks a way to show it from the file: an orbit camera for models, first person for levels, mip levels and channels for textures, a slice view for volumes. The arrow keys step through the rest of the folder, as in a picture viewer.

Its own renderer

Physically based glTF materials, glass that refracts what is behind it, ambient occlusion in the creases, and splats sorted on the GPU. Vulkan on Linux, Direct3D 12 on Windows, Metal on macOS.

Large scenes

The copies of one mesh are drawn in one call. On a laptop with an RTX 5070 Ti, that took a USD forest of 100,000 trees from 73.6 ms a frame to 3.4 ms. Models appear before all their textures have loaded.

  • Animation

    Play a character's clips, or add the clips of an animation library, retargeted between humanoid skeletons with foot IK. Move a MetaHuman's face with its own rig controls.

  • Reloads when you save

    When an editor or exporter saves the file, Slerp offers to reload it and keeps the camera, the clip and its time.

  • Scans and science

    Window and level CT scans, slice through NIfTI, NRRD and HDF5 volumes, and read FITS, DICOM and whole-slide images.

  • The desktop's look

    Colours, fonts and icons come from KDE, GNOME, Windows or macOS.

Inside a file

The pieces inside a file

The Contents panel lists what a file holds: nodes, meshes, materials, textures, clips, layers and archive entries. Click one to see it on its own. Point at one and the 3D view outlines it.

  • Drag it out

    Drag a piece out of the window, or copy it with Ctrl+C, and it lands as an ordinary file. Pictures come out exactly as stored, meshes and clips as GLB, sounds as WAV and music as MIDI.

  • Saving as GLB

    File, Save as GLB writes the scene you see, with skins, morph targets and clips. Slerp's tests check the output with the Khronos glTF Validator.

    slerp convert lqdm1.bsp lqdm1.glb

  • Archives open like folders

    WADs, PAKs, PK3s, VPKs and Unity packages list their entries, and the selected one shows in the view. Slerp reads and extracts, and never changes your files.

What each reader covers and what it leaves out

Safety

Careful with what it reads

A thumbnailer reads the files you scroll past, downloads included, so Slerp treats each file as possibly hostile. It is written in Rust, and the riskier C and C++ decoders run in separate processes. That lowers the risk of a bad file without ruling it out.

  • 38

    Fuzz targets

    The parsers are fed broken and random input with cargo-fuzz, and truncated and corrupted files are part of the test suite.

  • Checked

    Sizes and offsets

    Readers check sizes and offsets before using them and cap the memory they use, so a damaged file should get a message, not a crash or a hang.

  • Isolated

    Risky decoders apart

    The C decoders for JPEG XR, HEIC and AV1, the MetaHuman reader and the PDF and SVG renderers run in child processes with time and memory limits.

  • Offline

    No network

    Slerp never goes online. No accounts, no telemetry, no update checks. Your files stay on your computer.

Packages

Install

No releases yet. Slerp is a young project with one developer, Eric. Until the first release, each package builds from the source with one script. Most of the testing so far has been on one Linux laptop with KDE, a Windows 11 virtual machine and one Mac, so expect files it gets wrong. Bug reports are welcome on GitHub, most of all with a file you are free to share.

Debian and Ubuntu

Package coming

A .deb with the thumbnailer, viewer and menu entry, and an optional Qt plugin package for KDE.

tools/build-deb.sh
cd local/dist
sudo apt install ./slerp_0.1.0-1_amd64.deb

Arch Linux

AUR coming

A PKGBUILD for slerp and slerp-qt-plugin. Put the source tarball beside it and build.

tools/source-tarball.sh
makepkg -si

Windows 11

Zip coming

Unpack the zip into a folder that stays put, then register it once. No installer, no administrator rights.

slerp.exe register

macOS

App coming

Slerp.app for Apple Silicon, with a Quick Look extension for Finder. Builds with Rust and the Command Line Tools.

tools/macos-app.sh install

From source

Works today

Rust 1.93 or newer, a C and C++ compiler and libclang. The README lists where each file goes.

cargo build --release

Using Dolphin? Run slerp associate --apply once, then restart Dolphin, so it lists Slerp among its preview plugins.
